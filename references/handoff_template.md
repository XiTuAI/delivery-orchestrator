# 交付交接与沟通模板

所有跨 Agent 交互遵循「**正文精简（≤16 KiB）+ 长文档传绝对路径 + 状态统一落在唯一交接记录**」原则。

---

## 1. 单一任务交接记录模板（每个任务仅维护 1 份）

优先复用项目已有 issue；若无 issue，则在项目约定目录（如 `docs/deliveries/<任务编号>.md`）维护本文件。

```markdown
# 交付交接记录：<任务编号> <需求简称>

## 基本绑定（首次核对后固定）
- **任务编号**：<任务编号>
- **仓库绝对路径**：<REPO_ABS_PATH>
- **Antigravity 会话**：<AG_CHAT_UUID>
- **Codex 会话**：<CODEX_CHAT_UUID>
- **需求/设计文档**：<绝对路径或 issue 链接>
- **工作分支 / PR**：<分支名 / PR 链接，未建填 待创建>

## 当前状态
- **当前阶段**：阶段 <1..8>（<阶段名>）
- **当前负责人**：Antigravity / Codex / 客户
- **等待状态**：进行中 / 等待 Codex 输出 / 等待客户验收 / 等待合并部署结果
- **最近一次派单回执**：`<MSG_UUID>`（状态：`queued` / `confirmed`，仅代表投递）
- **下一步**：<具体可执行的下一步动作>

## 待答问题
| 编号 | 提出方 | 问题描述 | 建议方案 | 状态 | 结论 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Q1 | Codex | ... | ... | 待答复 / 已闭环 | ... |

## 关键交付与验证记录
- **开发检查结果**：<实际运行命令、结果、未覆盖项>
- **独立 CR 结论**：<审查结论、已修复阻塞项>
- **预检与验收信息**：<预览地址/启动方式、已知限制、验收轮次>

## 上线四项独立状态（严禁合并填写）
- [ ] **客户验收通过**：未通过 / 已通过（时间与客户确认依据）
- [ ] **代码已合并**：未合并 / 已合并（PR 链接 + Merge Commit SHA）
- [ ] **部署成功**：未部署 / 部署中 / 成功 / 失败（部署记录或当前线上实际状态）
- [ ] **线上验证通过**：未验证 / 通过 / 失败（线上版本号 + 关键流程验证证据）
```

## 2. 阶段 2 派单模板：需求评审

```markdown
【任务编号】<任务编号>
【当前阶段】阶段 2：需求评审
【仓库绝对路径】<REPO_ABS_PATH>
【需求文档】<需求文档绝对路径或链接>
【设计稿/原型】<设计稿路径或链接，无则写无>
【交接记录】<交接记录绝对路径或 issue 链接>

### 请你完成以下事项
1. 先阅读仓库相关代码，对照需求文档与验收标准做工程评审。
2. 指出需求歧义、遗漏场景、受影响模块及风险，并对每个问题给出你的建议方案。
3. 若无阻塞疑问，可直接继续输出「阶段 3：技术方案与任务拆解」（小改动可合并成一段）；若方案会改变产品行为或验收标准，请先停下来向我对齐。

### 结果交到哪里
- 将评审结论与待答问题写入上述【交接记录】，并在本 Codex 会话简要回报。
```

## 3. 需求答复 / 推进开发模板

```markdown
【任务编号】<任务编号>
【当前阶段】阶段 2→3/4（答复评审疑问并继续推进）
【交接记录】<交接记录绝对路径或 issue 链接>

### 对疑问的答复
- Q1：<明确结论；若更新了需求/AC，注明文档已同步更新>

### 请你继续完成
1. 按已对齐的需求与方案，在项目约定分支实现并完成联调与相关测试。
2. 提 PR（附任务编号、改动摘要、测试证据、验证步骤），并安排独立审查上下文做 CR、修复阻塞项后重跑检查。
3. 完成后将 PR、待验收版本/预览或启动方式、实际运行的检查与未覆盖项、已知限制写入【交接记录】并在会话简要回报。
4. 注意：当前严禁合并主干或部署，需等客户验收通过后再由我下达合并上线指令。
```

```markdown
2. **AC-2（边界/异常场景）**：操作步骤 → 预期结果

确认无误请回复 **“客户验收通过”**（我随后安排 Codex 合并上线）；如需调整，请直接指出问题项，我整理后派回 Codex 修复。
```

## 5. 客户验收退回整改派单模板

```markdown
【任务编号】<任务编号>
【当前阶段】阶段 6：客户验收退回整改（第 N 轮）
【交接记录】<交接记录绝对路径或 issue 链接>
【关联 PR】<PR 链接>

### 客户验收退回项（已由交付负责人整理）
1. **[必须修复] <问题标题>**：现状 vs 预期行为 / 验收标准。
2. ...

### 请你完成
1. 在原 PR 分支修复上述问题，补充/重跑相关测试，并对新增 diff 做独立 CR。
2. 更新 PR 与【交接记录】（写明修复点、实际运行的检查与结果、新的待验收版本信息）并在会话简要回报。
3. 严禁直接合并或部署，修复完成后交回我复检并重新组织客户验收。
```

## 6. 阶段 7 派单模板：客户验收通过 → 合并上线

```markdown
【任务编号】<任务编号>
【当前阶段】阶段 7：合并上线（已获客户明确验收通过）
【交接记录】<交接记录绝对路径或 issue 链接>
【目标 PR】<PR 链接>

### 客户验收确认依据
- <客户确认时间与原话摘要>

### 请你完成
1. 核对 CI、分支保护与人工 reviewer 状态满足合并条件，按项目现有流程合并 PR。
2. 按项目现有流程部署；若合并自动触发部署，请持续跟踪该次部署直到完成。
3. 验证线上版本号与关键用户流程。
4. 将 PR、合并 commit SHA、部署结果、线上验证证据写入【交接记录】并在会话简要回报；若部署失败，按项目既有流程止损并如实报告当前线上状态。
```
